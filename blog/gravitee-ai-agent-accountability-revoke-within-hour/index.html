Gravitee: only 6% can revoke a rogue AI agent's access within an hour

Gravitee's survey of 900 US and UK technology leaders found 52% had an agent related incident in the past year, yet only 6% can revoke a rogue agent's access within an hour.

GovernanceSecurityEnterprise adoption

On November 9, Gravitee published the third wave of its State of AI Agent Security research, a survey of 900 senior technology leaders in the US and UK fielded in October by Opinion Matters1. The share of organizations running more than 150 agents rose from 7% to 16% since the April wave, and 52% reported an agent related security or privacy incident in the past year1. Gravitee sells agent management software, so read its framing with care, though the gaps it measures are specific.

Control has not kept pace with fleet size. Gravitee says only 1 in 8 respondents can fully reconstruct what an agent did 30 days ago, only 6% can revoke a rogue agent's access within an hour, and fewer than 1 in 10 have a named person formally accountable for what their agents do1. When IT Brief covered the first wave in February, that survey of 750 leaders found 47% of agents running without oversight2. In the new wave, the share of agents monitored and secured moved only from 56% to 57%1.

Confidence is falling while fleets grow. Respondents who said they were very prepared for an agent incident fell from 47% to 29%, and 58% have already had to revoke an agent's access during a live incident1. Afterward, only 25% held a named person responsible and 17% changed nothing1. Teams are pulling the plug, then skipping the review that would stop the next one.

Reconstructing an agent's actions a month later is a lineage and audit problem for data teams. If agents query the warehouse through a shared service account, query history shows the account, not the agent or its owner. Gravitee also found 97% run agents that call other agents1, so one request can cross several hops before it touches a table. Per agent roles, query tags that carry the agent name and request ID, and log retention longer than 30 days make reconstruction possible. Fast revocation depends on knowing exactly which grants each agent holds.

One step this week: pick one agent that reads production data and run a drill. Using only your logs, reconstruct what it queried on a day last month, then time how long it takes to revoke its access. Write down who owns it.
