AI, applied

AI where it removes real work

I don't start with the model. I start with the question people keep asking, the business rule behind it and the data that answers it. Once I understand the root cause, I automate the part that repeats.

Asking the warehouse a question in plain English

I built an LLM-based NL-to-SQL agent over the data mart and its Looker tables. It can only read. It blocks PII, forces the filters every query needs, and pins down what "last quarter" means instead of guessing.

The chat front ends add a trust layer: a confidence score, a plain account of how the question was read, and the SQL it ran, right there on screen.

About

The longer version

I started in 2014 in Hyderabad, writing SQL Server stored procedures for a healthcare migration. Members, providers, claims, eligibility. It taught me early that a migration is really a long list of business rules, and every one of them has to be proven.

In 2018 I moved onto an e-commerce data platform for a global direct-selling company, and I'm still on it. I've worked on it across two employers, first as an engineer building pipelines out of AS400 and PostgreSQL, and today as the architect who owns it. It's a 1 TB Redshift data mart with more than 200 tables, and about 63 operating companies report from it.

A lot of my best work is plain engineering. A job that took 12 hours now takes 30 minutes. Four clusters share data instead of syncing it. A replication pipeline no longer needs babysitting. A 3-year reservation didn't get signed because the cost model left out the option that mattered most.

More recently I've been putting AI to work on the same platform: an NL-to-SQL agent that shows its SQL, agents that handle the questions my team gets every week, and Copilot running on governed semantic models.

I lead a team of ten. I care about standards, root causes and numbers you can trace back to their source.
